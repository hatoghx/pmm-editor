# 作業の手順

## 1. 概要

PMM と EMM を書き換える作業の手順をまとめます。

| 作業 | 節 |
| --- | --- |
| すべての作業に共通する進め方 | 2 |
| モデルとアクセサリの複製、削除、並べ替え、移植 | 3 |
| 外部親とカメラの追従の変更 | 4 |
| モーションの取り出しと取り込み | 5 |
| 壊れた PMM の修復と救出 | 6 |
| パッケージ化（収集）とパスの再リンク | 7 |
| ゼロからの作成 | 8 |
| そのほかの整理 | 9 |

節番号の「PMM 5.2」は [PMM ファイル形式](02-pmm-format.md)、「EMM 7 章」は [EMM ファイル形式](03-emm-format.md)、「関係 2.3」は [ファイル同士の関係](06-relations.md) を指します。

## 2. 共通の進め方

### 2.1 流れ

1. 原本を書き換えず、別の名前で書き出す。
2. PMM の文字コードを決める（2.2）。
3. PMM を最後のバイトまで読む。読み終えた位置がファイルの大きさと一致することを確かめる。
4. 同じフォルダに同じ名前の EMM があれば読む（関係 2.1）。
5. 中身を書き換える。
6. キーの連鎖とモデル ID を組み立て直して書き出す（2.3、2.4）。
7. EMM の番号を振り直して、PMM と同じ名前で書き出す（2.5）。
8. 書き出したファイルを読み直し、3 の確認をもう一度行う。

### 2.2 文字コードの決め方

PMM にも EMM にも文字コードの記録はありません。次の順で決めます。

1. 利用者が文字コードを指定していれば、それを使う。
2. モデル名、ボーン名、パスを CP932 として読み、壊れた文字がなければ CP932 とする。
3. 壊れた文字があれば GBK（CP936）で読み直し、壊れた文字がなければ GBK とする。
4. どちらでも読めないときは、利用者に尋ねる。

書き出すときは、読んだときと同じ文字コードを使います。別の文字コードへ直すときの決まりは 9.3 にあります。

### 2.3 キーの連鎖の組み立て直し

キーを足したり消したりした後は、previous、next、ID を作り直します。

1. 要素（ボーン、モーフなど）ごとに、キーをフレームの昇順に並べる。
2. フレーム 0 のキーを初期レコードにする。フレーム 0 のキーがなければ作る。
3. 初期レコードの ID を、ボーンとモーフでは要素の添字、そのほかの列では 0 とする。
4. 残りのキーに、初期レコードの数から始まる連番の ID を振る。ボーンなら、ボーン数を最初の ID にする。
5. 各キーの previous を一つ前のキーの ID、next を一つ後のキーの ID にする。最後のキーの next は 0、初期レコードの previous は 0 にする。
6. 追加レコードを ID の昇順に書き出し、その前に件数を書く。

### 2.4 モデル ID の付け直し

モデルを足したり消したりした後は、モデル ID を書き出す順に 0 から振り直し、PMM 5.8 に挙げた参照先をすべて新しい ID に書き換えます。消したモデルを指していた参照の値は、外部親なら (−1, 0)、カメラとアクセサリの親なら −1 と 0 です。

### 2.5 EMM の番号の振り直し

1. 書き換える前の PMM から、物体ごとの EMM のキー（`Pmd2` など）を関係 2.3 の決まりで求めておく。
2. 書き換えた後の PMM から、同じ決まりで新しいキーを求める。
3. EMM を読み、物体ごとに古いキーから新しいキーへ付け替える。`[Object]`、すべての `[Effect]` と `[Effect@名前]` の行、`Owner` 行が対象になる。
4. 消した物体の行を除く。消した物体が `Owner` だったタブは、タブごと除く。`Owner` がない、または `[Object]` にない物体を指すタブがあると、MME は EMM 全体を読み込まない（EMM 9 章）。
5. `[Object]` を番号順に並べて書き出す。

行の文字列を置き換える方法はとりません（関係 2.8）。

### 2.6 守るべき上限

| 項目 | 上限 |
| --- | --- |
| モデル数、アクセサリ数 | それぞれ 255（u8 で数えるため） |
| 表示枠の数 | 255 |
| パスの長さ | 255 バイト（fix(256) の中に NUL が要る） |
| ボーン名、モーフ名 | 19 バイト |

## 3. モデルとアクセサリ

### 3.1 モデルを複製する

写したモデルは、モデルの並びと描画順で、元のモデルの直後に置きます。

| 手順 | 内容 | 書き換える場所 |
| --- | --- | --- |
| 1 | モデル数が 255 を超えないことを確かめる | |
| 2 | 元のモデルのブロックを丸ごと写す（名前、パス、一覧、全部のキー、現在状態、描画情報） | PMM 5.1 |
| 3 | 写したブロックを、モデルの並びで元のモデルの直後に入れる | PMM 5 章 |
| 4 | 描画順で元のモデルの直後に置き、後ろのモデルの描画順を 1 つずつ下げる | PMM 5.1 の項目 14 |
| 5 | 計算順も同じように元のモデルの直後に置く | PMM 5.7 |
| 6 | モデル ID を振り直し、参照を書き換える | 2.4 |
| 7 | 拡張部に、写したモデルの範囲選択の状態を足す | PMM 13 章 |
| 8 | 写したモデルの外部親は、元のモデルと同じ相手を指したままにする | PMM 5.4、5.6 |
| 9 | EMM の番号を振り直す（2.5） | |

複数のモデルを一度に複製し、その中のモデル同士が外部親でつながっているときは、写したモデルの外部親を、写した相手に向け直します。

### 3.2 エフェクトを付けたままモデルを複製する

3.1 の手順に、EMM の次の作業を加えます。

1. 2.5 の手順 1 で、元のモデルの古いキーを控える。
2. `[Object]` に、写したモデルの行を元のモデルと同じパスで足す。
3. すべての `[Effect]` と `[Effect@名前]` で、元のモデルの行（`.show`、`[n]`、`[n].show` を含む）を写し、キーを写したモデルのものにして、元の行の直後に入れる。
4. 2.5 の手順 2 以降で番号を振り直す。

元のモデルが `Owner` になっているタブ（オフスクリーン描画）は増やしません。写したモデルが受け継ぐのは、元のタブの中の割り当てだけです。

### 3.3 アクセサリを複製する

3.1 と同じ流れで、次の点が違います。

- 描画順は 0 から数える（PMM 8.2 の項目 4）。
- 元のアクセサリが後描画の開始位置より前にあるときは、後描画の開始位置（PMM 9.1 の項目 28）に複製した数を足す。
- アクセサリには計算順と外部親がない。

### 3.4 モデルやアクセサリを削除する

1. 消すモデルを指す参照を外す（2.4）。
2. 選択モデルが消すモデルなら、選択を外す（0 にする）。
3. ブロックを除き、描画順と計算順を詰める。
4. 消したアクセサリのうち、後描画の開始位置より前にあった数だけ、後描画の開始位置を減らす。
5. モデル ID を振り直す（2.4）。
6. EMM の番号を振り直し、消した物体の行を除く（2.5）。

### 3.5 描画順を並べ替える

1. 描画順を書き換える。モデルは 1 から、アクセサリは 0 から、欠番なく振る。
2. EMM の番号を振り直す（2.5）。描画順が変わると EMM の番号が変わるためです。

### 3.6 別の PMM からモデルを移植する

| 手順 | 内容 |
| --- | --- |
| 1 | 移植元と移植先の両方に、同じ名前の EMM があることを確かめる |
| 2 | 移植元のモデルのブロックを写し、移植先のモデルの並びの末尾に足す |
| 3 | 描画順は、移植先で選んだモデルの直後（選んでいなければ最後）に、移植元での順を保って入れる |
| 4 | 計算順は、移植先の最後に、移植元での順を保って足す |
| 5 | 外部親は、一緒に移植したモデルを指すものだけ写した相手に向け直し、ほかは (−1, 0) にする |
| 6 | モデル ID を振り直す（2.4） |
| 7 | 移植先の EMM の番号を振り直す（2.5） |
| 8 | 移植元の EMM から、移植したモデルの行を移植先の EMM へ写す。移植先に同じ名前の `[Effect@名前]` がないタブの行は写さず、写さなかった件数を利用者に伝える |

## 4. 外部親とカメラの追従

### 4.1 特定のボーンの外部親をすべて消す

あるボーンの外部親を、キーと現在状態のすべてから外す手順です。

1. モデル名でモデルを探す。同じ名前が複数あれば、利用者にどれかを尋ねる。
2. ボーン名で、ボーン名の一覧（PMM 5.1 の項目 7）の添字 b を求める。
3. 外部親にできるボーンの添字の一覧（PMM 5.1 の項目 13）で、b が何番目にあるかを求め、その位置を j とする。先頭の −1 も数に入れる。b が一覧にないときは、そのボーンは外部親を持てないので、作業はない。
4. 表示・IK・外観のキー（初期レコードと追加レコードのすべて）で、外部親の j 番目の組を (−1, 0) にする（PMM 5.4）。
5. 外部親の現在状態の j 番目で、親のモデル ID を −1、親のボーンの添字を 0 にする（PMM 5.6）。開始フレームと終了フレームはそのまま残す。

モデルのすべてのボーンの外部親を外すときは、j を 1 から最後まで変えて 4 と 5 を行います。

### 4.2 外部親を付ける

4.1 の 4 と 5 で、(−1, 0) の代わりに、親のモデル ID と親のボーンの添字を書きます。親のモデル ID が 0 以上なら、親のボーンは実在するボーンでなければなりません（PMM 5.4）。

外部親で別のモデルに追従するモデルは、計算順を相手より後にします。

### 4.3 カメラの追従先を変える

| 対象 | 書き換える場所 |
| --- | --- |
| キーごとの追従先 | カメラのキーの親のモデル ID とボーンの添字（PMM 6.2） |
| 現在の追従先 | 色と追従の設定の項目 3 と 4（PMM 12 章） |
| 追従のオンとオフ | 色と追従の設定の項目 6 |

## 5. モーションの取り出しと取り込み

### 5.1 モデルのモーションを VMD に取り出す

1. 文字コードを決める（2.2）。中国語の Windows で作られた PMM は GBK です。
2. モデルを探し、取り出すボーン（またはモーフ）の添字を求める。
3. 初期レコードから next をたどり、そのボーンのキーをすべて集める（PMM 2.3）。フレーム 0 の初期キーも含める。
4. キーを VMD のボーンのキーに直す（関係 4.1）。補間曲線は VMD 3.1 の並びに直す。
5. 名前を、使う人の環境の文字コードで書く（関係 4.3）。日本語の MMD で使うなら CP932 にする。CP932 で表せない名前が含まれていたら、利用者に知らせる。
6. ボーン名が 15 バイトを超えていないかを確かめる。超えていたら、VMD を読み込んでも元のボーンに結び付かないことを利用者に知らせる。
7. VMD のヘッダのモデル名にモデル名を書く。

モデル全体を取り出すときは、すべてのボーン、すべてのモーフ、表示・IK・外観のキーを同じように直します。

### 5.2 カメラのモーションを VMD に取り出す

1. カメラのキーをすべて集め、VMD のカメラのキーに直す。補間曲線は VMD 5.1 の順序に直す。
2. 必要なら照明とセルフシャドウのキーも入れる。
3. ヘッダのモデル名を `カメラ・照明` にする。

カメラの追従先（親のモデルとボーン）は VMD に入りません。

### 5.3 VMD を PMM に取り込む

1. VMD のボーン名と同じ名前のボーンを、モデルのボーン名の一覧から探す。見つからない名前のキーは入れない。
2. 同じフレームにキーがあれば上書きし、なければ足す。
3. 物理は有効（物理オフのバイトを 0）にする。
4. 連鎖を組み立て直す（2.3）。
5. 最終フレーム（PMM 5.1 の項目 21）を、キーの最大フレーム以上にする。

## 6. 壊れた PMM の修復と救出

### 6.1 壊れ方の見分け

| 症状 | 原因の例 | 節 |
| --- | --- | --- |
| 読み込めるが、MMD で物体が飛ぶ、表示されない、落ちる | 物理演算の発散で、値が非数や極端に大きな数になった | 6.2 |
| 途中で読み込みが止まる | ファイルが途中で切れている、またはバイトが壊れている | 6.3 |
| 読み込めるが、キーが抜ける、順番が乱れる | キーの連鎖が壊れている | 6.4 |

### 6.2 値のあふれを直す

次の値が非数、無限大、または絶対値 3.40282 × 10^38 以上のとき、0.001 に置き換えます。

| 対象 | 値 |
| --- | --- |
| ボーン | キーと現在状態の移動、回転 |
| アクセサリ | キーと現在状態の位置、回転 |
| カメラ | キーと現在状態の位置、ずれ、回転、距離 |
| 重力 | キーと現在状態の加速度、向き |

照明の色、モーフのウェイト、エッジの太さ、アクセサリの透明度と拡大は対象にしません。物理演算と関係しないためです。

### 6.3 途中で切れた PMM からモーションを救い出す

1. 先頭から仕様のとおりに読み、読めたモデルのブロックを残す。どこで止まったかを記録する。
2. 止まったモデルのブロックでは、ボーンのキー、モーフのキーの順に、読めたところまでを残す。
3. 読めたモデルごとに 5.1 の手順で VMD に取り出す。
4. カメラの区分まで読めていれば、5.2 の手順でカメラも取り出す。

途中のバイトが壊れていて読み進められないときは、次のモデルのブロックの先頭を探して読み直します。モデルのブロックの先頭は、モデル ID（u8）、長さの付いた名前 2 つ、`.pmx` や `.pmd` で終わる 256 バイトのパスの順です。パスの文字列を手がかりに位置を探し、名前の長さが合う位置から読み直してください。

### 6.4 キーの連鎖を直す

1. 要素ごとに、初期レコードと、その要素に属する追加レコードを集める。連鎖が壊れていて所属が分からないキーは捨てる。
2. 2.3 の手順で連鎖を組み立て直す。

### 6.5 修復した後の確認

1. 書き出した PMM を読み直し、最後のバイトまで読めることを確かめる。
2. すべてのキーの連鎖が PMM 2.3 の決まりを満たすことを確かめる。

## 7. パッケージ化とパスの再リンク

### 7.1 パッケージ化（収集）

PMM が使うファイルをすべて一つのフォルダに集め、そのフォルダだけで開けるようにします。集める先の形の例です。

| 出力先 | 中身 |
| --- | --- |
| `<出力先>\<PMM の名前>.pmm` | パスを書き換えた PMM |
| `<出力先>\<PMM の名前>.emm` | パスを書き換えた EMM |
| `<出力先>\Files\Models\000\` から | モデルと、その依存ファイル。モデルごとに 3 桁の番号のフォルダ |
| `<出力先>\Files\Accessories\000\` から | アクセサリと依存ファイル |
| `<出力先>\Files\Media\` | 音声、背景動画、背景画像 |
| `<出力先>\Files\` の下 | EMM が参照するエフェクト。元の階層を保つ |
| `<出力先>\manifest.txt` | 集めたファイルの一覧（UTF-8） |

手順は次のとおりです。

1. PMM のモデル、アクセサリ、音声、背景動画、背景画像のパスを、実在するファイルに直す。相対パスは PMM のフォルダ、MMD の実行フォルダの順に探す。
2. 各ファイルの依存ファイルをたどる（7.2）。
3. 依存ファイルを、元のファイルとの相対的な位置を保って写す。
4. PMM のパスを、写した先の絶対パスに書き換える。255 バイトを超えたら中止する。
5. EMM のパス（`[Object]` とエフェクトの行）を写した先に書き換える。
6. PMM と EMM を、元と同じ文字コードで書き出す。

### 7.2 依存ファイルのたどり方

| 元のファイル | 依存ファイル |
| --- | --- |
| pmx | 材質のテクスチャ、スフィア、トゥーン。共有トゥーン（番号で指すもの）と `screen.bmp` は MMD が用意するので集めない |
| pmd | 材質のテクスチャ名（`*` で区切られた複数の名前） |
| x（テキスト形式） | 中に書かれたテクスチャのファイル名。同じ名前の fx があればそれも |
| x（バイナリ形式） | たどれない。利用者に知らせる |
| fx、fxsub | `#include` の参照と、引用符の中の拡張子付きファイル名。たどった先の fx もさらにたどる |

依存ファイルの相対パスは参照しているファイルのフォルダ、大元のファイルのフォルダ、両者に共通するフォルダの順に探します。

### 7.3 パスの再リンク（移設）

フォルダごと別の場所へ移したプロジェクトの、PMM と EMM の中の絶対パスを新しい場所へ書き換えます。壊れたパスを探して直す作業ではありません。

1. 移す前の共通のフォルダ（置換元）を決める。PMM の場所と、PMM と EMM のすべての絶対パスに共通する最も深いフォルダとする。
2. 移した後のフォルダ（置換先）を決める。
3. EMM の `UserFile` で始まる相対パス（EMM 5.2）を、次の順で絶対パスに直す。
   1. 置換元の下にある `UserFile` フォルダで見つかれば、その絶対パスにして書き換えの対象にする。
   2. MMD の実行フォルダの `UserFile` だけで見つかれば、共有の素材とみなして書き換えない。
   3. どちらにもなければ、作業を中止して一覧を示す。
4. すべての絶対パスについて、置換元で始まる部分を置換先に置き換える。置換元で始まらないパスが一つでもあれば、何も変えずに中止して一覧を示す。
5. 新しい PMM と、同じ名前の EMM を書き出す。

## 8. ゼロからの作成

モデルとモーションを指定して、PMM を新しく作る手順です。

### 8.1 手順

1. 8.2 の値で、モデルとアクセサリのない PMM の骨組みを作る。
2. モデルごとに、PMX から一覧を作る（[PMX の参照部分](05-pmx-reference.md) の 4 章）。パスは絶対パスで書く。
3. モデルごとに 8.3 の値でブロックを作る。
4. モーションの VMD を 5.3 の手順で取り込む。カメラの VMD があれば、カメラのキーに取り込む。
5. 再生の終了フレームと、各モデルの最終フレームを、キーの最大フレーム以上にする。
6. 2.3 と 2.4 の手順で書き出す。

### 8.2 PMM 全体の値

実ファイルで多く見られた値です。MMD を新しく起動したときの値と同じとは限りません。

| 項目 | 値 |

## 9. そのほかの整理

### 9.1 余分なキーを消す

次のキーは、消しても再生の結果が変わりません。

| 対象 | 消すキー |
| --- | --- |
| ボーン | 前後のキーと、移動、回転、物理の有無がすべて同じ間のキー。先頭と最後のキーは残す |
| ボーン | すべてのキーが移動 0、回転なしで、物理の有無も変わらないボーンでは、初期キー以外のすべて |
| モーフ | 前後のキーとウェイトが同じ間のキー。先頭と最後は残す |

補間曲線は判定に使いません。前後の値が同じなら、曲線の形に関係なく、その間の値は変わらないためです。

### 9.2 物理演算を切る

物理演算のモード（PMM 9.1 の項目 31）を 0 にします。

### 9.3 文字コードを変える

1. 元の文字コードで PMM と EMM を読む（2.2）。
2. 名前とパスを新しい文字コードで書けるかを確かめる。書けない文字があれば、利用者に知らせて止める。
3. ボーン名とモーフ名は、新しい文字コードで 19 バイトを超えないかを確かめる。超える名前は、MMD が読み込むときに PMX の名前と一致しなくなる。
4. 新しい文字コードで書き出す。
