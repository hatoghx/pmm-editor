# 基礎知識

## 1. 役割

PMM と EMM を扱うために必要な前提をまとめます。ほかの文書もここで定めた言葉を使います。

## 2. ソフトウェア・ツール

| 名前 | 内容 |
| --- | --- |
| MikuMikuDance（MMD） | 3D の人形を動かして動画を作る Windows 用の無料ソフト。本資料はバージョン 9.32 を基準にする |
| MikuMikuEffect（MME） | MMD に組み込んで使う追加ソフト。シェーダーで描画の見た目を変える |

## 3. ファイルタイプ

| 拡張子 | 名前 | 中身 | 作るソフト |
| --- | --- | --- | --- |
| pmm | プロジェクトファイル | シーン全体（使うモデルとアクセサリ、全部の動き、カメラ、照明、画面の設定） | MMD |
| emm | エフェクト割り当てファイル | どの物体にどのエフェクトを付けたか | MME |
| emd | モデル単位の割り当てファイル | 1 つの物体ぶんのエフェクトの割り当て | MME |
| pmx | モデル | 人形の形、骨組み、表情 | モデル作者 |
| pmd | 古い形式のモデル | pmx と同じ役割 | モデル作者 |
| x | アクセサリ | 動かない小物や背景（DirectX の形式） | 作者 |
| vmd | モーション | 動きだけを取り出したデータ。モデル用とカメラ用がある | MMD |
| fx、fxsub | エフェクト | MME が使うシェーダーのプログラム | 作者 |

PMM はモデルやアクセサリのファイルを中に含みません。ファイルのパスだけを記録します。そのため、PMM を別の場所へ移すと参照が切れることがあります。

## 4. シーン関連

| 言葉 | 意味 |
| --- | --- |
| モデル | pmx または pmd のファイルから読み込んだ人形や舞台。ボーンとモーフを持つ |
| アクセサリ | x などのファイルから読み込んだ物体。ボーンを持たず、位置、回転、拡大、透明度だけを動かせる |
| ボーン | モデルの骨。親子関係を持ち、移動と回転で形を動かす |
| モーフ | モデルの形を変える部品。目の開閉や口の形など。0 から 1 の重み（ウェイト）で効き方を決める |
| 材質 | モデルの面の塗り方のまとまり。MME は材質ごとにエフェクトを付けられる。EMM では「サブセット」と呼ぶこともある |
| 表示枠 | MMD の画面で、ボーンやモーフをまとめて見せるための見出し |
| IK | 足先などの位置を決めると、膝や腿の角度を自動で計算する仕組み。キーごとに有効と無効を切り替えられる |
| 外部親 | あるボーンを、別のモデルのボーン（または地面）に追従させる仕組み。手に持たせる小物などに使う |
| 付与 | あるボーンの回転や移動を、別のボーンに分け与える仕組み（PMX の機能） |
| 物理演算 | 髪やスカートを重力で揺らす計算。ボーンごと、キーごとに切ることができる |

## 5. フレーム

| 言葉 | 意味 |
| --- | --- |
| フレーム | 時間の単位。MMD は 1 秒を 30 フレームとして扱う |
| キーフレーム（キー） | ある時刻での値の記録。キーとキーの間は補間で求める |
| 補間曲線 | キーの間の変化の仕方。ベジェ曲線の制御点 2 つ（4 個の数）で表す |
| 初期キー | PMM が要素ごとに必ず 1 つ持つ、フレーム 0 のキー |

## 6. 順序

| 言葉 | 意味 |
| --- | --- |
| 描画順 | 物体を画面に描く順番。モデルとアクセサリでそれぞれ持つ |
| 後描画の開始位置 | アクセサリの描画順の境目。これより前のアクセサリはモデルより先に描かれ、残りはモデルの後に描かれる |
| 計算順 | モデルの動きを計算する順番。外部親で他のモデルに追従するモデルは、相手より後に計算する必要がある |

## 7. パス・文字コード

| 言葉 | 意味 |
| --- | --- |
| UserFile | MMD の実行ファイルと同じフォルダにある、素材を置くための標準のフォルダ |
| 絶対パス | `C:\` のようにドライブから書いたパス |
| 相対パス | どこかのフォルダを基準にしたパス。MMD と MME は基準の決め方に独自の決まりがある（[MMD の動作](08-mmd-behavior.md)） |
| ANSI コードページ | Windows の言語設定で決まる文字コード。番号で表す（下表） |

MMD と MME はファイルの中の文字列を、保存した環境の ANSI コードページで書きます。ファイルの中に文字コードの記録はないので、読み手が判断します。Windows の ANSI コードページになるものは、すべて対象です。主なものは次のとおりです。

| 番号 | 言語・地域 | 1 文字のバイト数 |
| --- | --- | --- |
| 874 | タイ語 | 1 |
| 932 | 日本語（Shift_JIS） | 1 または 2 |
| 936 | 簡体字中国語（GBK） | 1 または 2 |
| 949 | 韓国語 | 1 または 2 |
| 950 | 繁体字中国語（Big5） | 1 または 2 |
| 1250 | 中央ヨーロッパ | 1 |
| 1251 | キリル文字 | 1 |
| 1252 | 西ヨーロッパ（英語など） | 1 |
| 1253 | ギリシャ語 | 1 |
| 1254 | トルコ語 | 1 |
| 1255 | ヘブライ語 | 1 |
| 1256 | アラビア語 | 1 |
| 1257 | バルト語 | 1 |
| 1258 | ベトナム語 | 1 |

1 バイトのコードページでは、どのバイトも何かの文字になるので、読み誤っても壊れた文字が出ません。2 バイトを使うコードページ（932、936、949、950）では、名前を 19 バイトで切ると、2 バイト文字の途中で切れることがあります。
