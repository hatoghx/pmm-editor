# ファイル同士の関係

## 1. 概要

PMM は EMM、PMX、VMD と結び付いて使われます。本書ではその結び付きの決まりをまとめます。

| 組み合わせ | 章 |
| --- | --- |
| PMM と EMM | 2 |
| PMM と PMX | 3 |
| PMM と VMD | 4 |

## 2. PMM と EMM

### 2.1 置き場所と名前

EMM は PMM と同じフォルダに、拡張子だけを変えた同じ名前で置きます。PMM 側には EMM の名前やパスの記録がありません。二つを結び付けるのは、ファイル名が同じことだけです。

| PMM | 対応する EMM |
| --- | --- |
| `C:\MMD\scene\dance.pmm` | `C:\MMD\scene\dance.emm` |

### 2.2 自動の読み込みと保存

| 操作 | MME の動き |
| --- | --- |
| PMM を開く | 同じ名前の EMM があれば、自動で読み込む |
| PMM を保存する | 割当ファイルの自動保存が ON なら、同じ名前の EMM を保存する。ON が既定 |
| MME の「設定を保存」 | 任意の名前で EMM を保存する |
| MME の「設定を読込」 | 任意の EMM を読み込む |

### 2.3 オブジェクトの番号

EMM の `[Object]` の番号（`Pmd<番号>`、`Acs<番号>`）は、MMD の描画の順に 1 から振った通し番号です。モデルとアクセサリで一つの番号を共有します。PMM の値から、次の手順で求められます。

1. アクセサリを、描画順（PMM 8.2 の項目 4）の小さい順に並べる。
2. モデルを、描画順（PMM 5.1 の項目 14）の小さい順に並べる。
3. 後描画の開始位置（PMM 9.1 の項目 28）を k とする。
4. 次の順につなげ、先頭から 1、2、3 と番号を振る。
   1. 描画順が k より小さいアクセサリ
   2. すべてのモデル
   3. 描画順が k 以上のアクセサリ

### 2.4 番号の例

アクセサリ 3 個、モデル 2 体、後描画の開始位置が 1 の場合です。

| PMM での種類と描画順 | EMM のキー |
| --- | --- |
| アクセサリ、描画順 0 | `Acs1` |
| モデル、描画順 1 | `Pmd2` |
| モデル、描画順 2 | `Pmd3` |
| アクセサリ、描画順 1 | `Acs4` |
| アクセサリ、描画順 2 | `Acs5` |

### 2.5 PMM のモデル ID との違い

EMM の番号は PMM のモデル ID（PMM 5.1 の項目 1）やアクセサリ ID とは別のものです。モデル ID は 0 から始まり、描画順とは関係なく振られます。EMM の番号を、PMM のモデル ID から直接求めることはできません。

### 2.6 読み込み時の照合

MME は EMM を読み込むとき、`[Object]` の行とシーンの物体を、番号でなくパスで結び付けます。

1. モデルかアクセサリかの種類が同じものだけを比べる。
2. パスを、そのまま、絶対パスに直したもの、EMM のフォルダを基準に直したもの、の順に比べる。大文字と小文字は区別しない。片方が他方の後ろの部分と一致する場合も同じとみなす。
3. 見つからなければ、ファイル名と拡張子だけで比べる。
4. それでも結び付かない物体は、一覧にして利用者に知らせる。

結び付いた後は、`[Effect]` などの行のオブジェクト名（`Pmd2` など）を、その物体として扱います。

### 2.7 ずれが起きる場合

EMM と PMM は別々の時点で保存されることがあります。そのため、EMM の番号の並びが PMM と合わない場合があります。

| 場面 | 起きること |
| --- | --- |
| EMM を保存した後に、描画順を変えて PMM だけを保存した | 番号の並びが PMM の描画順と合わない |
| モデルやアクセサリを差し替えた | `[Object]` のパスが PMM のパスと合わない |
| 同じファイルのモデルを複数読み込んだ | ファイル名だけの照合では、どれに結び付くかが決まらない |

照合はパスで行うので、番号の並びがずれても割り当ては復元されます。パスが合わなくなると、その物体の割り当ては失われます。

### 2.8 PMM を書き換えるときに EMM で必要なこと

| PMM での変更 | EMM で必要な変更 |
| --- | --- |
| ファイル名を変えて保存する | EMM も同じ名前で保存する |
| モデルやアクセサリのパスを変える | `[Object]` の同じ物体のパスを変える |
| 物体の追加、削除、描画順の変更 | 2.3 の決まりで番号を振り直し、すべてのセクションのオブジェクト名（`Owner` 行を含む）を書き換える |
| 後描画の開始位置の変更 | 同上 |

番号を振り直すときは、EMM を読み込んで物体ごとに番号を付け替え、書き出し直します。行の文字列を置き換える方法をとると、`C:\MMD\Pmd3\stage.fx` のようなパスの中の文字まで書き換えてしまいます。

## 3. PMM と PMX

### 3.1 PMM が PMX から写して持つもの

PMM はモデルごとに、ボーン名、モーフ名、IK の一覧、外部親にできるボーンの一覧、表示枠の数を持ちます。作り方は [PMX の参照部分](05-pmx-reference.md) の 4 章です。キーフレームはこの一覧の添字の順に並ぶので、一覧と PMX が食い違うと、キーがどのボーンのものかが変わります。

### 3.2 MMD が PMM を開くときの照合

MMD は PMM のモデルを開くとき、パスの PMX を読み込み、PMM の一覧と比べます。

| 比べる項目 | 一致したとき | 一致しないとき |
| --- | --- | --- |
| ボーン数と名前 | 添字のまま読む | 名前でボーンを対応させる。PMX にない名前のキーは捨てる |
| モーフ数と名前 | 添字のまま読む | 名前で対応させる。PMX にない名前のキーは捨てる |
| 表示枠の数 | 開閉の状態を使う | 開閉の状態を捨てる |

一覧が一致しないとき、MMD は「モデルの構造が PMM 保存時と違う」という内容の確認を出します。

### 3.3 モデルファイルを差し替えるとき

同じボーン名を持つ別のモデルに差し替えると、3.2 の照合で動きはそのまま引き継がれます。名前が合わないボーンとモーフのキーは失われます。

## 4. PMM と VMD

### 4.1 項目の対応

| PMM の項目 | VMD の項目 | 注意 |
| --- | --- | --- |
| ボーンのキー（PMM 5.2） | ボーンのキー（VMD 3 章） | ボーンの添字の代わりにボーン名を書く。補間曲線は並べ替える |
| モーフのキー（PMM 5.3） | モーフのキー（VMD 4 章） | モーフ名を書く |
| 表示・IK・外観のキー（PMM 5.4） | 表示と IK のキー（VMD 8 章） | 外部親は VMD に入らない |
| カメラのキー（PMM 6.2） | カメラのキー（VMD 5 章） | 補間曲線の 1 本の中の順序を変える。カメラの親は VMD に入らない |
| 照明のキー（PMM 7.2） | 照明のキー（VMD 6 章） | |
| セルフシャドウのキー（PMM 11.2） | セルフシャドウのキー（VMD 7 章） | |
| アクセサリのキー（PMM 8.3） | なし | VMD では表せない |
| 重力のキー（PMM 10 章） | なし | VMD では表せない |

### 4.2 名前の長さ

VMD のボーン名とモーフ名は 15 バイトまで、PMM は 19 バイトまでです。16 バイトから 19 バイトの名前は VMD に書くと切れてしまい、読み込み時に元のボーンと結び付かないことがあります。

### 4.3 文字コード

VMD の名前は、モデルを使う環境の ANSI コードページで書きます。中国語の環境で作られた PMM（GBK）から日本語の環境用の VMD を作るときは、名前を GBK で読み、CP932 で書き直します。CP932 で表せない文字を含む名前は、変換できません。
