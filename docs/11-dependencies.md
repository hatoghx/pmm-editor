# 依存ファイルと配置

## 1. 概要

PMM が使うファイルと、そのファイルが参照するファイルをすべてたどって集め、利用者の望む配置で並べるための文書です。たどり方は 2 章から 4 章、並べ方は 5 章にあります。手順の全体は [作業の手順](09-operations.md) の 7 章にあります。

## 2. 参照の全体

| 参照元 | 参照先 | 書かれている場所 |
| --- | --- | --- |
| PMM | モデル（pmx、pmd）、アクセサリ（x、vac）、音声、背景動画、背景画像 | PMM の各パス（PMM 5.1、8.2、9.1） |
| PMM | EMM | 同じ名前（関係 2.1） |
| EMM | エフェクト（fx、fxsub など） | `[Object]` とエフェクトの行（EMM 5 章、7 章） |
| モデル | 同じ名前の EMD | モデルのファイル名の拡張子を emd に替えたもの（3.5） |
| EMD | エフェクト | `Obj`、`Obj[n]` の行（3.5） |
| pmx | テクスチャ、スフィア、トゥーン | テクスチャ表と材質（3.1） |
| pmd | テクスチャ、スフィア、トゥーン | 材質とトゥーン名の表（3.2） |
| x | テクスチャ | `TextureFilename`（3.3） |
| vac | x | 2 行目（3.4） |
| fx、fxsub | fx、fxsub、テクスチャ | `#include` と引用符の中のファイル名（3.6） |

PMM は VMD のパスを持ちません。動きは PMM の中にあるので、集める対象には入りません。VMD として渡すときは、[作業の手順](09-operations.md) の 5.1 と 5.2 で取り出します。

## 3. 参照の読み方

### 3.1 pmx

pmx のテクスチャ表と材質の読み方は、[PMX の参照部分](06-pmx-reference.md) の 5 章にあります。共有トゥーンと `screen.bmp` は集めません。

### 3.2 pmd

先頭から次の順に読みます。

| 順 | 項目 | 大きさ |
| --- | --- | --- |
| 1 | 識別、バージョン、モデル名、コメント | 3 + 4 + 20 + 256 byte |
| 2 | 頂点 | 件数（u32）と、38 byte × 件数 |
| 3 | 面 | 添字の件数（u32）と、2 byte × 件数 |
| 4 | 材質 | 件数（u32）と、70 byte × 件数 |
| 5 | ボーン | 件数（u16）と、39 byte × 件数 |
| 6 | IK | 件数（u16）と、IK ごとに 11 byte + 2 byte × 影響ボーンの数 |
| 7 | 表情 | 件数（u16）と、表情ごとに 20 + 4 + 1 byte + 16 byte × 頂点の数 |
| 8 | 表情の表示 | 件数（u8）と、2 byte × 件数 |
| 9 | ボーン枠の名前 | 件数（u8）と、50 byte × 件数 |
| 10 | ボーン枠のボーン | 件数（u32）と、3 byte × 件数 |
| 11 | 英名の有無 | u8。1 のとき、モデル名 20、コメント 256、ボーン名 20 × ボーン数、表情名 20 ×（表情数 − 1）、ボーン枠名 50 × 枠の数 |
| 12 | トゥーンの名前の表 | 100 byte × 10 |

材質 70 byte のうち、参照を読むのに必要なのは次の 2 つです。

| 位置（先頭から。0 から数える） | 項目 | 内容 |
| --- | --- | --- |
| 44 | トゥーンの番号（u8） | 0 から 9 はトゥーンの名前の表の番号。255 は指定なし |
| 50 | テクスチャ名（20 byte） | 最初の NUL までが値。`*` で区切られたときは、前がテクスチャ、後がスフィア（`.sph` と `.spa`） |

トゥーンの名前の表は `toon01.bmp` から `toon10.bmp` が標準で、これらは MMD が用意します。標準と違う名前（例：`toon_hada.bmp`）はモデルのフォルダにあるファイルとして集めます。

テクスチャのパスは pmd のあるフォルダが基準です。

### 3.3 x

先頭が `xof 0302txt` のテキスト形式の x は、`TextureFilename { "ファイル名"; }` の形でテクスチャを参照します。パスは x のあるフォルダが基準です。先頭が `xof 0302bin` のバイナリ形式の x は、たどれません。

### 3.4 vac

vac はアクセサリの設定を書いたテキストファイルで、次の 6 行からなります。

| 行 | 内容 |
| --- | --- |
| 1 | アクセサリの名前 |
| 2 | x のファイル名 |
| 3 | 拡大率 |
| 4 | 位置（x, y, z） |
| 5 | 回転角（x, y, z） |
| 6 | ボーン名（アクセサリが動きに従うボーン） |

2 行目の x を集める対象にします。x のパスは vac のあるフォルダが基準です。

### 3.5 EMD

モデルのファイルと同じフォルダに、拡張子だけを変えた同じ名前の EMD があれば、MME が読み込むときに自動で適用されます（EMM の付録 A）。EMD は `[Info]` と `[Effect]` からなり、`[Effect]` の `Obj` と `Obj[n]` の値がエフェクトのパスです（EMM 7 章の形式）。このエフェクトを集める対象にします。相対パスの基準は MMD の実行ファイルのあるフォルダです（EMM 5.2）。

### 3.6 fx と fxsub

テキストとして読み、コメント（`//` から行末まで、`/*` と `*/` の間）を除いて、次の 2 種類を参照とします。

- `#include` の参照先
- 引用符の中にある、拡張子付きのファイル名（テクスチャ、fxsub など）

たどった先が fx や fxsub なら、さらにたどります。

`#define` で指定された名前（例：`ALBEDO_MAP_FILE "albedo.png"`）は、同じ fx にある切り替え（例：`ALBEDO_MAP_FROM 3`）によって、使われない場合があります。見つからなかったときは、見つからなかったものの一覧に入れ、エラーにはしません。

拡張子が pmx、pmd、x の名前は、エフェクトが対象にするオブジェクトを選ぶための名前で、ファイルの参照ではありません。集める対象にしません。

## 4. たどる手順

1. 大元のファイル（PMM のモデル、アクセサリ、音声、背景、EMM のエフェクト）を作業の一覧に入れる。PMM のパスは実在するファイルに直す（MMD の動作 2.2）。
2. 一覧から未処理のファイルを 1 つ取り、種類に応じて 3 章で参照を読む。
3. 参照のパスを参照しているファイルのあるフォルダ、大元のファイルのあるフォルダ、両者に共通するフォルダの順に探す。見つからなければ、種類（テクスチャなど）と名前を見つからなかったものとして記録する。
4. 見つかったファイルのうち、集めない種類（MMD が用意する共有トゥーンと `screen.bmp`）を除き、まだ一覧にないものを一覧に入れる。同じファイルを二度たどらない。
5. 一覧が空になるまで 2 から 4 を繰り返す。
6. 集めたファイルの一覧と、見つからなかったものの一覧を利用者に知らせる。

## 5. 配置の方式

### 5.1 共通の条件

- 参照先のパスは参照元からの相対位置で書かれています。参照元とその依存ファイルの間の相対位置は、写した後も保ちます。保たないと、pmx のテクスチャや fx の `#include` が見つからなくなります。
- そのため、モデル 1 体ぶんのファイル（pmx、pmd、テクスチャ、スフィア、トゥーン、EMD）は種類で分けず、元の階層のまま 1 つのフォルダの下に写します。
- EMM と EMD の中の相対パスのエフェクトは、MMD の実行ファイルのあるフォルダを基準に探されます。写した後は、写したエフェクトの絶対パスに書き換えます。
- 相対位置を保てないときは、中止して利用者に知らせます。例：依存ファイルが別のドライブにある。
- 複数のモデルが同じテクスチャを使うときは、モデルごとのフォルダに 1 つずつ写し、各モデルのフォルダを単独で成り立たせます。エフェクトは EMM から参照するので、1 つだけ写します。
- 同じ名前のフォルダやファイルがぶつかるときは、番号を付けて区別します（例：`Model_2`）。
- PMM に書く絶対パスは 255 byte 以下で、PMM の文字コードで表せなければなりません（検証 4、5 章）。

### 5.2 方式

| 方式 | 配置 | 向いている場合 |
| --- | --- | --- |
| 元の階層を保つ | 共通のフォルダ（7.3 の置換元と同じ決め方）を根にして、各ファイルを元の相対位置に写す | 後で元の場所に戻す、または元の構成のまま渡す |
| プロジェクト単位 | `<出力先>\<プロジェクト名>\` の下に、PMM、EMM、モデル、アクセサリ、エフェクト、メディアを写す。構成は [作業の手順](09-operations.md) の 7.1 の例 | プロジェクトを 1 つのフォルダで渡す |
| アセット単位 | 種類ごとに、利用者が名前を決めたフォルダを作る。例：モデルは `<モデル用の名前>\<モデルの名前>\`、アクセサリは `<アクセサリ用の名前>\`、エフェクトは `<エフェクト用の名前>\`、動きは `<アニメーション用の名前>\`。モデルのフォルダの中は 5.1 のとおり元の階層のまま | 素材を種類ごとに整理して管理する |
| モデル単位 | モデルごとにフォルダを作り、その中にモデルと依存ファイル、そのモデルの EMD、そのモデルの動き（VMD）を入れる | モデルと動きを組にして渡す |

どの方式でも PMM と EMM の中のパスは写した先のパスに書き換えます。動き（VMD）を入れる方式では、PMM から VMD を取り出して（作業 5.1、5.2）、利用者が指定したフォルダに書きます。

### 5.3 利用者に確かめること

| 確かめる内容 | 例 |
| --- | --- |
| 方式 | 元の階層を保つ、プロジェクト単位、アセット単位、モデル単位、またはこれ以外 |
| 出力先と、フォルダやファイルの名前 | 種類ごとのフォルダの名前、プロジェクトの名前 |
| 動きを渡すか | 渡すなら、モデルごとか、1 つにまとめるか、カメラも含めるか、VMD の文字コード |
| 集める範囲 | EMM とエフェクト、EMD、メディアを含めるか |
| 見つからなかったものの扱い | 知らせて続けるか、中止するか |

指定が方式に当てはまらないときは、5.1 の条件を満たす範囲で、利用者の指定どおりに並べます。

### 5.4 集めた後の確認

1. 書き出した PMM と EMM の、すべてのパスが実在することを確かめる（検証 5 章）。
2. pmx、pmd、x、fx の参照が写した先でも見つかることを 4 章の手順でもう一度確かめる。
3. 一覧にあるすべてのファイルが写されたことを確かめる。
