## 2. PMM 与 EMM

### 2.1 位置与名称

EMM 放在与 PMM 相同的文件夹中，使用相同的名称、不同的扩展名。PMM 中没有记录 EMM 的名称和路径，两个文件只靠名称相同而关联。

| PMM | 对应的 EMM |
| --- | --- |
| `C:\MMD\scene\dance.pmm` | `C:\MMD\scene\dance.emm` |

### 2.2 自动读取与保存

| 操作 | MME 的行为 |
| --- | --- |
| 打开 PMM | 如果有同名的 EMM，则读取 |
| 保存 PMM | 开启了分配文件的自动保存时，保存同名的 EMM。默认开启 |
| MME 的“保存设置” | 以任意名称保存 EMM |
| MME 的“读取设置” | 读取任意 EMM |

### 2.3 物体的编号

`[Object]` 的编号（`Pmd<编号>`、`Acs<编号>`），是按 MMD 的绘制顺序从 1 开始的连续编号。模型与配件共用该编号序列。可以由 PMM 按下列方式推出。

1. 将配件按绘制顺序（PMM 8.2 的项目 4）从小到大排列。
2. 将模型按绘制顺序（PMM 5.1 的项目 14）从小到大排列。
3. 设后绘制的起始位置（PMM 9.1 的项目 28）为 k。
4. 将下列内容依次连接，从头开始编号 1、2、3……。
   1. 绘制顺序小于 k 的配件
   2. 全部模型
   3. 绘制顺序大于等于 k 的配件

### 2.4 编号示例

配件 3 个、模型 2 个，后绘制的起始位置为 1 的情况：

| PMM 中的种类与绘制顺序 | EMM 的键 |
| --- | --- |
| 配件，绘制顺序 0 | `Acs1` |
| 模型，绘制顺序 1 | `Pmd2` |
| 模型，绘制顺序 2 | `Pmd3` |
| 配件，绘制顺序 1 | `Acs4` |
| 配件，绘制顺序 2 | `Acs5` |

### 2.5 与 PMM 的模型 ID 的区别

EMM 的编号与 PMM 的模型 ID（PMM 5.1 的项目 1）和配件 ID 是不同的东西。模型 ID 从 0 开始，与绘制顺序无关。无法直接由 PMM 的模型 ID 得出 EMM 的编号。

### 2.6 读取时的对应

MME 读取 EMM 时，不是按编号，而是按路径将 `[Object]` 的行与场景中的物体联系起来。

1. 只比较相同种类（模型或配件）的物体。
2. 依次比较：按原样书写的路径、转换为绝对路径的路径、以 EMM 的文件夹为基准解析的路径。忽略大小写。一方的末尾与另一方一致时，也视为相同。
3. 都不对应时，只比较文件名与扩展名。
4. 仍然没有对应的物体，列出后通知用户。

对应之后，`[Effect]` 等区段中的物体名（`Pmd2` 等）作为该物体处理。

### 2.7 编号发生偏差的情况

EMM 与 PMM 有时在不同的时间点保存。因此 EMM 的编号排列可能与 PMM 不一致。

| 情形 | 发生的情况 |
| --- | --- |
| 保存 EMM 之后，更改了绘制顺序，只保存了 PMM | 编号排列与 PMM 的绘制顺序不一致 |
| 替换了模型或配件 | `[Object]` 的路径与 PMM 的路径不一致 |
| 多次读入了同一文件的模型 | 路径相同的物体全部对应 EMM 中第一条匹配的记录，该记录的分配只应用于最后被匹配的物体。其他物体没有分配 |

对应按物体的种类（模型还是配件）与路径进行。依次比较完整的路径、转换为绝对路径的形式、以 EMM 的文件夹为基准的相对路径、路径的末尾，都不一致时只比较文件名。由于按路径对应，即使只是编号偏差，分配也能恢复。路径不一致时，该物体的分配会丢失。

### 2.8 改写 PMM 时 EMM 所需的操作

| PMM 的更改 | EMM 所需的更改 |
| --- | --- |
| 用其他文件名保存 | 用相同名称保存 EMM |
| 更改模型或配件的路径 | 更改 `[Object]` 中同一物体的路径 |
| 增加、删除物体，或更改绘制顺序 | 按 2.3 的规则重新编号，并改写所有区段（包括 `Owner` 行）中的物体名 |
| 更改后绘制的起始位置 | 同上 |

重新编号时，读入 EMM、按物体重新编号后再写出。如果直接替换行中的文字，`C:\MMD\Pmd3\stage.fx` 这样的路径内部的字符也会被改掉。

## 3. PMM 与 PMX

### 3.1 PMM 从 PMX 复制的内容

PMM 为每个模型保存骨骼名、表情名、IK 的列表、可拥有外部亲的骨骼的列表以及显示框的数量。生成方法见 [PMX 的参照部分](06-pmx-reference.md)的第 4 章。关键帧按这些列表的索引排列，因此如果列表与 PMX 不一致，关键帧就会落到不同的骨骼上。

### 3.2 MMD 打开 PMM 时的对应

MMD 打开 PMM 中的模型时，从保存的路径读取 PMX，并与 PMM 中的列表比较。

| 比较的项目 | 一致时 | 不一致时 |
| --- | --- | --- |
| 骨骼数与名称 | 按索引读取 | 按名称对应骨骼。PMX 中不存在的名称的关键帧被丢弃 |
| 表情数与名称 | 按索引读取 | 按名称对应表情。PMX 中不存在的名称的关键帧被丢弃 |
| 显示框的数量 | 使用开合状态 | 数量不等于 PMX 的显示框数量、也不比它大 1 时，MMD 可能崩溃（PMM 5.8） |

列表不一致时，MMD 会提示“模型的结构与保存 PMM 时的不同”的确认。

### 3.3 替换模型文件

如果将模型替换为骨骼名相同的其他模型，动作会通过 3.2 的对应而保留。名称不一致的骨骼和表情的关键帧会丢失。

## 4. PMM 与 VMD

### 4.1 项目的对应

| PMM 的项目 | VMD 的项目 | 备注 |
| --- | --- | --- |
| 骨骼关键帧（PMM 5.2） | 骨骼关键帧（VMD 第 3 章） | 写入骨骼名而不是骨骼索引。重新排列插值曲线 |
| 表情关键帧（PMM 5.3） | 表情关键帧（VMD 第 4 章） | 写入表情名 |
| 显示、IK、外部亲关键帧（PMM 5.4） | 显示与 IK 关键帧（VMD 第 8 章） | 外部亲不保存在 VMD 中 |
| 相机关键帧（PMM 6.2） | 相机关键帧（VMD 第 5 章） | 改变每条插值曲线内部的顺序。相机的父级不保存在 VMD 中 |
| 照明关键帧（PMM 7.2） | 照明关键帧（VMD 第 6 章） | |
| 自阴影关键帧（PMM 11.2） | 自阴影关键帧（VMD 第 7 章） | |
| 配件关键帧（PMM 8.3） | 无 | 无法用 VMD 表达 |
| 重力关键帧（PMM 第 10 章） | 无 | 无法用 VMD 表达 |

### 4.2 名称的长度

VMD 的骨骼名与表情名限制为 15 byte，PMM 允许 19 byte。16 到 19 byte 的名称写入 VMD 时会被截断，读取时可能与原来的骨骼对应不上。

### 4.3 字符编码

VMD 的名称，用使用模型的环境的 ANSI 代码页书写。由其他环境制作的 PMM 生成 VMD 时，用原来的代码页读取名称，再用使用环境的代码页重新写入。例如，由 936 的 PMM 生成日语环境用的 VMD 时，用 936 读取名称，再用 932 重新写入。包含重新写入的代码页无法表示的字符的名称，无法转换。
