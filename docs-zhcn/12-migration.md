# 迁移

## 1. 概要

本文档说明将工程移到其他文件夹、其他驱动器或其他电脑，并使其在目标位置能够打开的步骤。内容是为在用户自己的电脑上运行的 AI 代理（桌面版 Claude Code、Codex 等）而写的，用于在本地执行“把这个文件夹中的这个工程移到那个文件夹”之类的指示。文件的收集与布局见[打包](11-dependencies.md)，路径的检查见[安全性检验](10-validation.md)。

## 2. 迁移的种类

| 种类 | 内容 | 原文件 |
| --- | --- | --- |
| 复制 | 复制到目标位置，保留原文件 | 保留 |
| 移动 | 复制到目标位置，确认完成后删除原文件 | 最后删除 |
| 移到其他电脑 | 目标位置的 MMD 执行文件夹与原来不同 | 按用户的指定 |

## 3. 需要向用户确认的事项

| 内容 | 示例 |
| --- | --- |
| 要移动的内容 | 原文件夹，以及其中的 PMM（有多个时，是哪一个） |
| 目标位置 | 目标文件夹。是否存在，是否为空 |
| 种类 | 复制还是移动 |
| 目标位置的 MMD 执行文件夹 | 移到其他电脑时 |
| 存在同名文件时 | 覆盖、加编号、中止 |
| 移动的范围 | 仅工程文件夹，还是也包含 MMD 的 `UserFile` 中的共享素材 |

无法确认的事项，不要凭推测决定，而要询问用户。

## 4. 步骤

1. 调查原工程。按[打包](11-dependencies.md)第 4 章的步骤，列出与 PMM 同名的 EMM、PMM 使用的文件以及它们的依赖文件。
2. 检查目标位置。确认文件夹可写入、路径长度（255 byte 以下）、文件名中没有不可使用的字符、能用 PMM 的字符编码表示（[安全性检验](10-validation.md)第 4 章、第 5 章）。
3. 出示计划。列出哪些文件复制到哪里、改写哪些路径，向用户出示并取得同意。存在同名文件时，按第 3 章中用户的指定处理。
4. 复制。不改动原文件。依赖文件保持与原文件的相对位置复制（[打包](11-dependencies.md)的 5.1）。
5. 改写路径。按第 5 章的步骤，改写复制出的 PMM 与 EMM。
6. 确认。重新读取复制出的 PMM 与 EMM 直到最后，确认所有路径都实际存在（[安全性检验](10-validation.md)第 3 章、第 5 章）。将复制的文件数量与大小，与原文件核对。
7. 仅限移动：到第 6 步为止没有问题时，询问用户是否可以删除原文件，取得同意后再删除。删除时优先放入回收站。

## 5. 路径的改写

对整个文件夹一并搬迁后的工程，改写 PMM 与 EMM 中的绝对路径，使其指向新的位置。PMM 的路径写在 fix(256) 之中（PMM 2.1、2.2），EMM 的路径按 EMM 5.2 的形式书写。这不是对失效路径的搜索。

1. 确定搬迁前的共同文件夹（源根）：PMM 所在位置以及 PMM 与 EMM 中所有绝对路径共有的最深的文件夹。
2. 确定搬迁后的文件夹（目标根）。
3. 将 EMM 中以 `UserFile` 开头的相对路径（EMM 5.2），按下列顺序转换为绝对路径。
   1. 在源根之下的 `UserFile` 文件夹中找到时，采用该绝对路径，并纳入改写对象。
   2. 仅在 MMD 执行文件夹的 `UserFile` 中找到时，视为共享素材，不改写。
   3. 两处都找不到时，停止并显示列表。
4. 对所有绝对路径，将开头的源根替换为目标根。只要有路径不以源根开头，就在不做任何更改的情况下停止，并显示列表。
5. 写出新的 PMM 与同名的 EMM。

## 6. 移到其他电脑时

- PMM 的路径中含有 `UserFile` 时，会先在目标位置的 MMD 执行文件夹的 `UserFile` 之下查找（[MMD 的行为](08-mmd-behavior.md) 2.2）。
- EMM 与 EMD 中的相对路径，以目标位置的 MMD 执行文件夹为基准查找（[EMM 文件格式](04-emm-format.md) 5.2）。
- 共享卡通使用目标位置的 MMD 执行文件夹的 `Data` 中的文件，因此不收集（[MMD 的行为](08-mmd-behavior.md) 2.4）。
- 目标位置的 MMD 中没有的素材，要收集并复制。

## 7. 代理必须遵守的事项

- 不改动原文件。改写只针对复制出的文件。
- 删除、覆盖这类无法恢复的操作，执行前先向用户确认。
- 将结果（复制的文件数、改写的路径数、未找到的项目）告知用户。
- 中途失败时，询问用户是清理还是保留目标位置。原文件没有被改动，保持原样。
