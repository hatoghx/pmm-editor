# PMM 文件格式

## 1. 概要

PMM 是 MMD 的工程文件。模型、镜头、灯光、配件、关键帧、画面状态被汇总在一个二进制文件中。本文档说明 0002 版的格式。

术语的含义见[基础知识](02-basics.md)。与 PMX 的对应见 [PMX 的参照部分](06-pmx-reference.md)和[文件之间的关系](07-relations.md)，MMD 打开 PMM 时的行为见 [MMD 的行为](08-mmd-behavior.md)。

## 2. 表示法与通用结构

### 2.1 类型

| 表示 | 别名 | 内容 |
| --- | --- | --- |
| u8 | byte、uint8 | 无符号 1 byte 整数 |
| i32 | int、int32 | 有符号 4 byte 整数（小端） |
| f32 | float、single | IEEE 754 单精度浮点数（小端） |
| vec3 | Vector3 | 3 个 f32（x, y, z） |
| quat | Quaternion、Vector4 | 4 个 f32（x, y, z, w） |
| bool | | u8。0 为假，1 为真 |
| str8 | VString（可变长字符串） | 长度（u8）与该长度的 byte 序列 |
| fix(N) | CString（定长字符串） | N byte 定长的字符串。到第一个 NUL 为止是值，其余内容不定 |

### 2.2 字符串

- 字符编码是保存文件的环境的 ANSI 代码页（日语 Windows 为 932，简体中文 Windows 为 936 等。见基础 7 章的表）。
- fix(N) 的 NUL 之后，可能留有以前使用过的字符串的残余。读取时在第一个 NUL 处截断，写入时将 NUL 之后全部填 0。
- 路径是绝对路径或相对路径。相对路径的查找方式见 [MMD 的行为](08-mmd-behavior.md)的第 2 章。
- 骨骼名与表情名是将 PMX 的名称转换为 ANSI 代码页并截为 19 byte 的结果。在使用 2 byte 的代码页（932、936、949、950）中，也可能在 2 byte 字符的中间被截断。代码页无法表示的字符会丢失。

### 2.3 关键帧列表

任何关键帧列表都按以下顺序排列。

1. 初始记录（与要素数量相同，不带 ID）
2. 追加记录的数量（i32）
3. 追加记录（“ID（i32）与记录”，重复数量次）

| 列表 | 初始记录的数量 | 初始记录的 ID |
| --- | --- | --- |
| 骨骼 | 骨骼数 | 骨骼的索引 |
| 表情 | 表情数 | 表情的索引 |
| 显示、IK、外部亲 | 1 | 0 |
| 镜头、灯光、重力、自阴影 | 1 | 0 |
| 配件（每个配件一个） | 1 | 0 |

每条记录开头的 12 byte 是通用的。

| 项目 | 类型 | 内容 |
| --- | --- | --- |
| frame | i32 | 帧号。初始记录为 0 |
| previous | i32 | 同一要素的前一条记录的 ID |
| next | i32 | 同一要素的后一条记录的 ID。最后一条为 0 |

链的规则如下。

- 从初始记录沿 next 前进，该要素的关键帧按帧的升序排列。
- 第一条追加记录的 previous 是初始记录的 ID。
- 追加记录的 ID 在文件中按升序排列，取不小于初始记录数量的值。允许有空缺。
- 初始记录的 previous 是 MMD 不使用的值。有些文件的镜头和灯光中存有非 0 的值（镜头 14 个、灯光 4 个）。存入的值与链的最后一个 ID 不一致。读写时保持原值即可。

### 2.4 插值曲线

一条插值曲线为 4 byte（x1, y1, x2, y2），值为 0 到 127。每条曲线的 4 byte 连续存放。

| 对象 | 曲线顺序 | 大小 |
| --- | --- | --- |
| 骨骼 | X 移动、Y 移动、Z 移动、旋转 | 16 byte |
| 镜头 | X 移动、Y 移动、Z 移动、旋转、距离、视角 | 24 byte |

| 项目 | 类型 | 内容 |

### 5.8 模型 ID 与显示框的数量

模型 ID 是在 PMM 中指代模型的编号。以下位置会引用它。

- 头部的选择模型
- 外部亲（5.4 与 5.6）
- 镜头的父级（6.2）与镜头的跟随目标（第 12 章）
- 配件的父级（8.3 与 8.4）
- 扩展部（第 13 章）

在 MMD 保存的文件中，ID 不一定从 0 开始依次排列。写出时可以从 0 起重新编号。此时上述引用也都要按同一对应关系改写。

显示框的数量，对于有表情的模型，是 PMX 的显示框数量加 1（增加了表情框）。对于没有表情的模型，与 PMX 的显示框数量相同。在调查的 1,162 个中，有 1,149 个符合此规律，其余 13 个（有表情）与 PMX 的数量相同。只有当该数量与 PMX 的显示框数量相同或大 1 时，MMD 才能正确读取。取其他值时，读取过程中可能崩溃（验证记录）。

| 有无范围选择 | bool | 仅为 1 时才有后续内容 |
| 范围选择的状态 | (u8, i32) × 模型数 | 模型 ID 与范围选择的对象 |

范围选择对象的值如下。

| 值 | 对象 |
| --- | --- |
| 0 | 全部帧 |
| 1 | 最初的骨骼 |
| 2 | 显示、IK、外部亲 |
| 3 | 选中的骨骼 |
| 4 | 选中的表情 |
| 5 | 全部表情帧 |
| 6 | 全部骨骼帧（仅限没有表情的模型） |
| 7 以后 | 按表情、骨骼的顺序分配的编号 |

## 附录 A. 与 0001 版的区别

0001 版是旧版 MMD 生成的格式。仅识别字符串末尾的数字为 `0001`。MMD 9.32 附带的示例 PMM 3 个，按下述结构都能读到最后一个 byte。

### A.1 头部

| 项目 | 与 0002 的区别 |
| --- | --- |
| 画面状态 | 6 byte（0002 为 7 byte）。对应 0002 的第 2 个到第 7 个 |
| 模型数之后 | 紧接着排列模型数个 20 byte 的名称 |

### A.2 模型

| 顺序 | 项目 | 类型 |
| --- | --- | --- |
| 1 | 模型 ID | u8 |
| 2 | 模型名 | fix(20) |
| 3 | 模型的路径 | fix(256) |
| 4 | 绘制顺序 | u8 |
| 5 | 显示 | bool |
| 6 | 选中的骨骼 | i32 |
| 7 | 选中的表情 | i32 × 4 |
| 8 | 显示框的数量与开合 | u8，以及该数量个 bool |
| 9 | 关键帧栏的纵向滚动、最终帧 | i32 × 2 |
| 10 | 骨骼的关键帧列表 | 初始记录为 57 byte × 骨骼数，追加记录为数量（i32）之后接 61 byte（ID 与 57 byte）× 数量 |
| 11 | 表情的关键帧列表 | 初始记录为 17 byte × 表情数，追加记录为数量之后接 21 byte × 数量 |
| 12 | 显示、IK 的关键帧列表 | 初始记录为 13 + IK 的数量 + 1 byte，追加记录前面带有 ID（i32） |
| 13 | 骨骼的当前状态 | 34 byte × 骨骼数（vec3、quat、bool × 2） |
| 14 | 表情的当前值、IK 的当前状态 | f32 × 表情数，bool × IK 的数量 |

骨骼数、表情数（含基准）、IK 的数量，由模型文件（PMD）统计。没有外部亲的槽。

### A.3 其他区别

| 区块 | 与 0002 的区别 |
| --- | --- |
| 镜头关键帧 | 没有父模型 ID 和父骨骼的索引（70 byte） |
| 重力的关键帧 | 没有 |
| 配件的当前状态 | 末尾是 1 byte 的 bool（0002 为 2 byte 的 bool） |
| 编辑、播放、背景、绘制的设置 | 到画面捕捉的方式为止与 0002 相同 |

### A.4 末尾的读取条件

画面捕捉的方式之后，每个块都带有 1 byte 的标记（为 1 时后面还有下一个块），标记不为 1 则文件在此结束。块的顺序如下。

| 顺序 | 内容 |
| --- | --- |
| 1 | 后绘制的起始位置、地面阴影的亮度、每个模型的加算合成、每个配件的加算合成 |
| 2 | 地面阴影的透明、标记 |
| 3 | 每个模型的边缘粗细（f32）、标记 |
| 4 | 物理运算的模式、重力（加速度、噪声量、方向、噪声启用）、标记 |
| 5 | 自阴影的模式、范围、每个模型的设置、标记 |
| 6 | 自阴影的关键帧列表、标记 |
| 7 | 轮廓色（i32 × 3）、标记 |
| 8 | 背景设为黑色、标记 |
| 9 | 镜头的父级（模型 ID、骨骼索引）、镜头的父级列表、标记。该块必定存在 |
| 10 | 跟随姿态的矩阵、镜头跟随、跟随的抑制、标记 |
| 11 | 地面的物理、标记 |
| 12 | 每个模型的计算顺序 |

示例中，有在块 4 之后结束的、在块 11 之后结束的，以及在块 9 之后结束的。
