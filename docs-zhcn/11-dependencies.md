# 依赖文件与布局

## 1. 概要

本文档说明如何追踪 PMM 所使用的文件以及这些文件所引用的文件，将它们全部收集起来，并按用户希望的布局排列。第 2 章至第 4 章是追踪的方法，第 5 章是排列的方法。整体步骤见[操作步骤](09-operations.md)的第 7 章。

## 2. 引用的整体

| 引用方 | 引用目标 | 书写位置 |
| --- | --- | --- |
| PMM | 模型（pmx、pmd）、配件（x、vac）、音频、背景视频、背景图片 | PMM 中的各路径（PMM 5.1、8.2、9.1） |
| PMM | EMM | 相同的名称（关系 2.1） |
| EMM | 效果（fx、fxsub 等） | `[Object]` 与效果的行（EMM 第 5 章、第 7 章） |
| 模型 | 同名的 EMD | 将模型文件名的扩展名换成 emd（3.5） |
| EMD | 效果 | `Obj`、`Obj[n]` 的行（3.5） |
| pmx | 纹理、球面贴图、卡通 | 纹理表与材质（3.1） |
| pmd | 纹理、球面贴图、卡通 | 材质与卡通名称的表（3.2） |
| x | 纹理 | `TextureFilename`（3.3） |
| vac | x | 第 2 行（3.4） |
| fx、fxsub | fx、fxsub、纹理 | `#include` 与引号内的文件名（3.6） |

PMM 不保存 VMD 的路径。动作在 PMM 之中，因此不属于收集的对象。要以 VMD 形式交付时，按[操作步骤](09-operations.md)的 5.1 与 5.2 提取。

## 3. 引用的读取方法

### 3.1 pmx

pmx 的纹理表与材质的读取方法，见 [PMX 的参照部分](06-pmx-reference.md)的第 5 章。共享卡通与 `screen.bmp` 不收集。

### 3.2 pmd

从头开始按下列顺序读取。

| 顺序 | 项目 | 大小 |
| --- | --- | --- |
| 1 | 识别、版本、模型名、注释 | 3 + 4 + 20 + 256 byte |
| 2 | 顶点 | 数量（u32）及 38 byte × 数量 |
| 3 | 面 | 索引的数量（u32）及 2 byte × 数量 |
| 4 | 材质 | 数量（u32）及 70 byte × 数量 |
| 5 | 骨骼 | 数量（u16）及 39 byte × 数量 |
| 6 | IK | 数量（u16）及每个 IK 为 11 byte + 2 byte × 受影响骨骼的数量 |
| 7 | 表情 | 数量（u16）及每个表情为 20 + 4 + 1 byte + 16 byte × 顶点的数量 |
| 8 | 表情的显示 | 数量（u8）及 2 byte × 数量 |
| 9 | 骨骼框的名称 | 数量（u8）及 50 byte × 数量 |
| 10 | 骨骼框的骨骼 | 数量（u32）及 3 byte × 数量 |
| 11 | 有无英文名 | u8。为 1 时：模型名 20、注释 256、骨骼名 20 × 骨骼数、表情名 20 ×（表情数 − 1）、骨骼框名 50 × 框的数量 |
| 12 | 卡通名称的表 | 100 byte × 10 |

材质的 70 byte 中，读取引用所需的有以下 2 处。

| 位置（从开头起，从 0 开始数） | 项目 | 内容 |
| --- | --- | --- |
| 44 | 卡通编号（u8） | 0 至 9 是卡通名称表中的编号。255 为未指定 |
| 50 | 纹理名（20 byte） | 到第一个 NUL 为止是值。用 `*` 分隔时，前面是纹理，后面是球面贴图（`.sph` 与 `.spa`） |

卡通名称的表中，`toon01.bmp` 至 `toon10.bmp` 是标准名称，由 MMD 提供。与标准不同的名称（例如 `toon_hada.bmp`），作为模型文件夹中的文件收集。

### 3.3 x

以 `xof 0302txt` 开头的文本格式的 x，以 `TextureFilename { "文件名"; }` 的形式引用纹理。路径以 x 所在的文件夹为基准。以 `xof 0302bin` 开头的二进制格式的 x，无法追踪。

### 3.4 vac

vac 是记录配件设置的文本文件，由下列 6 行构成。

| 行 | 内容 |
| --- | --- |
| 1 | 配件的名称 |
| 2 | x 的文件名 |
| 3 | 放大率 |
| 4 | 位置（x, y, z） |
| 5 | 旋转角（x, y, z） |
| 6 | 骨骼名（配件跟随其动作的骨骼） |

第 2 行的 x 是收集的对象。x 的路径以 vac 所在的文件夹为基准。

### 3.5 EMD

如果在模型文件所在的文件夹中，有仅扩展名不同的同名 EMD，MME 读取时会自动应用（EMM 附录 A）。EMD 由 `[Info]` 与 `[Effect]` 构成，`[Effect]` 中 `Obj` 与 `Obj[n]` 的值是效果的路径（EMM 第 7 章的形式）。将这些效果作为收集的对象。相对路径的基准是 MMD 可执行文件所在的文件夹（EMM 5.2）。

### 3.6 fx 与 fxsub

作为文本读取，将下列 2 种作为引用。

- `#include` 的引用目标
- 引号内带扩展名的文件名（纹理、fxsub 等）

追踪到的目标是 fx 或 fxsub 时，继续追踪。

## 4. 追踪的步骤

1. 将根文件（PMM 的模型、配件、音频、背景，以及 EMM 的效果）放入工作列表。PMM 的路径要解析为实际存在的文件（MMD 的行为 2.2）。
2. 从列表中取出一个未处理的文件，按其种类依据第 3 章读取引用。
3. 引用的路径，依次在引用方文件所在的文件夹、根文件所在的文件夹、两者共同的文件夹中查找。找不到时，将种类（纹理等）与名称记录为未找到。
4. 在找到的文件中，除去不收集的种类（MMD 提供的共享卡通与 `screen.bmp`），将尚未在列表中的放入列表。同一个文件不追踪两次。
5. 重复第 2 步至第 4 步，直到列表为空。
6. 将已收集文件的列表与未找到的文件的列表，告知用户。

## 5. 布局的方式

### 5.1 共同的条件

- 引用目标的路径是以引用方为基准的相对位置书写的。复制之后，要保持引用方与其依赖文件之间的相对位置。否则 pmx 的纹理和 fx 的 `#include` 就会找不到。
- 因此，1 个模型的文件（pmx、pmd、纹理、球面贴图、卡通、EMD）不按种类拆分，而是保持原来的层级，复制到同一个文件夹之下。
- EMM 与 EMD 中以相对路径书写的效果，会以 MMD 可执行文件所在的文件夹为基准查找。复制之后，要改写为所复制效果的绝对路径。
- 无法保持相对位置时，中止并告知用户。例如：依赖文件位于另一个驱动器。
- 多个模型使用同一个纹理时，在每个模型的文件夹中各复制一份，使每个模型的文件夹都能独立成立。效果由 EMM 引用，因此只复制一份。
- 文件夹或文件的名称冲突时，用编号加以区分（例：`Model_2`）。
- 写入 PMM 的绝对路径必须在 255 byte 以下，并且能用 PMM 的字符编码表示（检验第 4 章、第 5 章）。

### 5.2 方式

| 方式 | 布局 | 适合的情形 |
| --- | --- | --- |
| 保持原来的层级 | 以共同的文件夹（与 7.3 的替换源相同的确定方法）为根，将各文件复制到原来的相对位置 | 之后要放回原处，或以原来的结构交付 |
| 按工程 | 在 `<输出>\<工程名>\` 之下，复制 PMM、EMM、模型、配件、效果、媒体。结构为[操作步骤](09-operations.md) 7.1 的示例 | 将工程作为一个文件夹交付 |
| 按素材 | 按种类创建由用户决定名称的文件夹。例：模型放在 `<模型用的名称>\<模型的名称>\`，配件放在 `<配件用的名称>\`，效果放在 `<效果用的名称>\`，动作放在 `<动画用的名称>\`。模型文件夹的内部，按 5.1 保持原来的层级 | 按种类整理素材进行管理 |
| 按模型 | 为每个模型创建文件夹，放入模型及其依赖文件、该模型的 EMD、该模型的动作（VMD） | 将模型与动作成套交付 |

无论哪种方式，PMM 与 EMM 中的路径都要改写为复制目标的路径。包含动作（VMD）的方式，要从 PMM 提取 VMD（步骤 5.1、5.2），写入用户指定的文件夹。

### 5.3 需要向用户确认的事项

| 确认的内容 | 示例 |
| --- | --- |
| 方式 | 保持原来的层级、按工程、按素材、按模型，或其他 |
| 输出位置，以及文件夹与文件的名称 | 各种类的文件夹名称、工程名 |
| 是否交付动作 | 交付时，按模型还是合并为一个，是否包含相机，VMD 的字符编码 |
| 收集的范围 | 是否包含 EMM 与效果、EMD、媒体 |
| 未找到的项目的处理 | 告知后继续，还是中止 |

用户的指定不属于上述任何方式时，在满足 5.1 的条件的范围内，按用户的指定排列。

### 5.4 收集之后的确认

1. 确认写出的 PMM 与 EMM 中的所有路径都实际存在（检验第 5 章）。
2. 按第 4 章的步骤，再次确认 pmx、pmd、x、fx 的引用在复制目标中也能找到。
3. 确认列表中的所有文件都已复制。
