# 操作步骤

## 1. 概要

本文档说明改写 PMM 与 EMM 的步骤。

| 操作 | 小节 |
| --- | --- |
| 所有操作通用的流程 | 2 |
| 模型与配件的复制、删除、排序、移植 | 3 |
| 外部亲与相机追踪的更改 | 4 |
| 动作的提取与导入 | 5 |
| 损坏的 PMM 的修复与抢救 | 6 |

“PMM 5.2”这样的引用指向 [PMM 文件格式](03-pmm-format.md)，“EMM 第 7 章”指向 [EMM 文件格式](04-emm-format.md)，“关系 2.3”指向[文件之间的关系](07-relations.md)。

## 2. 通用流程

### 2.1 流程

1. 不改写原文件，用其他名称写出。
2. 确定 PMM 的字符编码（2.2）。
3. 将 PMM 读到最后一个 byte。确认读完的位置与文件大小一致。
4. 如果同一文件夹中有同名的 EMM，则读取（关系 2.1）。
5. 进行更改。
6. 重新组建关键帧的链与模型 ID，然后写出（2.3、2.4）。
7. 重新为 EMM 编号，并以与 PMM 相同的名称写出（2.5）。
8. 重新读取写出的文件，再次进行第 3 步的确认。

### 2.2 字符编码的确定方法

PMM 和 EMM 中都没有字符编码的记录。按下列顺序确定。

1. 用户指定了字符编码时，使用该编码。
2. 手头有模型的 PMX 时，将 PMX 的骨骼名用候选代码页（基础 7 章的表）编码并截为 19 byte，采用与 PMM 的骨骼名一致的代码页。
3. 没有 PMX 时，用候选代码页读取 PMM 中模型与配件的路径，采用该路径的文件实际存在的代码页。
4. 名称与路径只有 ASCII 字符而无法缩小候选范围时，以及都不符合时，询问用户。

仅凭有无乱码无法决定。1 byte 的代码页（874、1250 至 1258）中，任何 byte 都会成为字符。

写出时，使用与读取时相同的字符编码。改为其他字符编码时的规则见 9.3。

### 2.3 关键帧的链的重新组建

增删关键帧之后，重新生成 previous、next 与 ID。

1. 对每个要素（骨骼、表情等），将关键帧按帧的升序排列。
2. 将第 0 帧的关键帧作为初始记录。没有第 0 帧的关键帧时，新建一个。
3. 初始记录的 ID，骨骼与表情为要素的索引，其他列表为 0。
4. 其余关键帧从初始记录的数量开始依次分配 ID。骨骼的第一个 ID 是骨骼数。
5. 各关键帧的 previous 设为前一个关键帧的 ID，next 设为后一个关键帧的 ID。最后的关键帧的 next 为 0，初始记录的 previous 为 0。
6. 写出数量，然后按 ID 升序写出追加记录。

### 2.4 模型 ID 的重新编号

增删模型之后，按写出的顺序从 0 起重新给模型 ID 编号，并将 PMM 5.8 中列出的引用全部改为新的 ID。指向被删除模型的引用，外部亲改为 (−1, 0)，相机与配件的父级改为 −1 和 0。

### 2.5 EMM 的重新编号

1. 由更改前的 PMM，按关系 2.3 的规则求出各物体的 EMM 键（`Pmd2` 等）。
2. 由更改后的 PMM，按同样的规则求出新的键。
3. 读入 EMM，将各物体从旧键改为新键。对象包括 `[Object]`、`[Effect]` 与 `[Effect@名称]` 的所有行，以及 `Owner` 行。
4. 去掉被删除物体的行。`Owner` 是被删除物体的标签页，整个标签页一并去掉。只要有标签页缺少 `Owner`，或指向 `[Object]` 中不存在的物体，MME 就完全不会读取该 EMM（EMM 第 9 章）。
5. 按编号顺序写出 `[Object]`。

不要对行中的文字做替换（关系 2.8）。

### 2.6 必须遵守的上限

| 项目 | 上限 |
| --- | --- |
| 模型数、配件数 | 各 255（因为用 u8 计数） |
| 显示框的数量 | 255 |
| 路径的长度 | 255 byte（fix(256) 中需要 NUL） |
| 骨骼名、表情名 | 19 byte |

## 3. 模型与配件

### 3.1 复制模型

复制出的模型，在模型的排列和绘制顺序中，放在原模型的正后方。

| 步骤 | 操作 | 依据 |
| --- | --- | --- |
| 1 | 确认模型数不超过 255 | |
| 2 | 复制原模型的整个块（名称、路径、各列表、全部关键帧、当前状态、绘制信息） | PMM 5.1 |
| 3 | 将复制的块，插入到模型排列中原模型的正后方 | PMM 第 5 章 |
| 4 | 在绘制顺序中也放在原模型的正后方，并将其后模型的绘制顺序各顺延 1 | PMM 5.1 的项目 14 |
| 5 | 在计算顺序中也放在原模型的正后方 | PMM 5.7 |
| 6 | 重新给模型 ID 编号，并更新引用 | 2.4 |
| 7 | 在扩展部加入复制模型的范围选择状态 | PMM 第 13 章 |
| 8 | 复制模型的外部亲，保持指向与原模型相同的对象 | PMM 5.4、5.6 |
| 9 | 重新给 EMM 编号（2.5） | |

一次复制多个模型，且这些模型之间以外部亲相连时，将复制出的模型的外部亲，改为指向对应的复制模型。

### 3.2 连同效果一起复制模型

在 3.1 的基础上追加以下 EMM 的步骤。

1. 在 2.5 的第 1 步中，记录原模型的旧键。
2. 在 `[Object]` 中，为复制模型添加一行，路径与原模型相同。
3. 在所有 `[Effect]` 与 `[Effect@名称]` 中，复制原模型的行（包括 `.show`、`[n]`、`[n].show`），将键改为复制模型的键，插入到原模型各行的正后方。
4. 从 2.5 的第 2 步起重新编号。

原模型作为 `Owner` 的标签页（离屏渲染）不会增加。复制模型只继承既有标签页内的分配。

### 3.3 复制配件

流程与 3.1 相同，不同点如下。

- 绘制顺序从 0 开始计数（PMM 8.2 的项目 4）。
- 原配件位于后绘制的起始位置之前时，将后绘制的起始位置（PMM 9.1 的项目 28）加上复制的个数。
- 配件没有计算顺序，也没有外部亲。

### 3.4 删除模型或配件

1. 清除指向被删除模型的引用（2.4）。
2. 删除的是选中的模型时，清除选择（设为 0）。
3. 去掉该块，并补齐绘制顺序与计算顺序中的空缺。
4. 后绘制的起始位置，减去位于其之前的被删除配件的个数。
5. 重新给模型 ID 编号（2.4）。
6. 重新给 EMM 编号，并去掉被删除物体的行（2.5）。

### 3.5 更改绘制顺序

1. 改写绘制顺序。模型从 1 开始、配件从 0 开始，不留空缺地编号。
2. 重新给 EMM 编号（2.5），因为更改绘制顺序会使 EMM 的编号改变。

### 3.6 从其他 PMM 移植模型

| 步骤 | 操作 |
| --- | --- |
| 1 | 确认移植源与移植目标双方都有同名的 EMM |
| 2 | 从移植源复制模型的块，追加到移植目标模型排列的末尾 |
| 3 | 绘制顺序中，插入到移植目标中所选模型的正后方（未选时放在最后），保持在移植源中的顺序 |
| 4 | 计算顺序中，添加到移植目标的末尾，保持在移植源中的顺序 |
| 5 | 指向一起移植的模型的外部亲，改为指向移植后的对象，其余设为 (−1, 0) |
| 6 | 重新给模型 ID 编号（2.4） |
| 7 | 重新给移植目标的 EMM 编号（2.5） |
| 8 | 将移植模型的行，从移植源的 EMM 复制到移植目标的 EMM。移植目标中不存在 `[Effect@名称]` 的标签页中的行不复制，并告知用户跳过的数量 |

## 4. 外部亲与相机追踪

### 4.1 去掉特定骨骼的全部外部亲

从所有关键帧和当前状态中，去掉某个骨骼的外部亲的步骤。

1. 按名称查找模型。有多个同名模型时，询问用户是哪一个。
2. 在骨骼名列表（PMM 5.1 的项目 7）中，求出骨骼名对应的索引 b。
3. 在可拥有外部亲的骨骼的索引列表（PMM 5.1 的项目 13）中，求出 b 是第几个（包含开头的 −1），记为 j。b 不在列表中时，说明该骨骼不能拥有外部亲，无需进行任何操作。
4. 在所有显示、IK、外部亲的关键帧（初始记录和全部追加记录）中，将第 j 个外部亲的组设为 (−1, 0)（PMM 5.4）。
5. 在第 j 个外部亲的当前状态中，将父模型 ID 设为 −1，父骨骼的索引设为 0（PMM 5.6）。开始帧与结束帧保持不变。

要去掉模型所有骨骼的外部亲时，让 j 从 1 变到最后，重复第 4 步和第 5 步。

### 4.2 添加外部亲

在 4.1 的第 4 步与第 5 步中，写入父模型 ID 与父骨骼的索引，而不是 (−1, 0)。父模型 ID 在 0 以上时，父骨骼必须是实际存在的骨骼（PMM 5.4）。

通过外部亲跟随其他模型的模型，在计算顺序中应排在对方之后。

### 4.3 更改相机的追踪目标

| 对象 | 写入位置 |
| --- | --- |
| 每个关键帧的追踪目标 | 相机关键帧的父模型 ID 与骨骼的索引（PMM 6.2） |
| 当前的追踪目标 | 颜色与追踪的设置的项目 3 与 4（PMM 第 12 章） |
| 追踪的开与关 | 颜色与追踪的设置的项目 6 |

## 5. 动作的提取与导入

### 5.1 将模型的动作提取为 VMD

1. 确定字符编码（2.2）。PMM 以创建它的环境的代码页书写。
2. 找到模型，求出要提取的骨骼（或表情）的索引。
3. 从初始记录沿 next 前进，收集该骨骼的全部关键帧（PMM 2.3）。包括第 0 帧的初始关键帧。
4. 将关键帧转换为 VMD 的骨骼关键帧（关系 4.1）。插值曲线按 VMD 3.1 的排列重新排列。
5. 名称用使用者环境的字符编码书写（关系 4.3）。用于日语 MMD 时使用 932。包含该代码页无法表示的名称时，告知用户。
6. 确认骨骼名没有超过 15 byte。超过时，告知用户读取该 VMD 时可能无法与原来的骨骼对应。
7. 在 VMD 头部的模型名中写入模型名。

提取整个模型时，同样转换所有骨骼、所有表情，以及显示、IK 的关键帧。

### 5.2 将相机的动作提取为 VMD

1. 收集所有相机关键帧，转换为 VMD 的相机关键帧。插值曲线按 VMD 5.1 的排列重新排列。
2. 需要时，也加入照明与自阴影的关键帧。
3. 头部的模型名设为 `カメラ・照明`。

相机的追踪目标（父模型与骨骼）不保存在 VMD 中。

### 5.3 将 VMD 导入 PMM

1. 对 VMD 的每个骨骼名，在模型的骨骼名列表中查找同名的骨骼。找不到的名称的关键帧不导入。
2. 同一帧已有关键帧时覆盖，否则添加。
3. 启用物理计算（将物理关闭的 byte 设为 0）。
4. 重新组建链（2.3）。
5. 将最终帧（PMM 5.1 的项目 21）设为不小于关键帧的最大帧。

## 6. 损坏的 PMM 的修复与抢救

### 6.1 损坏方式的辨别

| 症状 | 原因示例 | 小节 |
| --- | --- | --- |
| 可以读取，但物体飞走、不显示、MMD 崩溃 | 物理计算发散，值变成 NaN 或极大的数 | 6.2 |
| 读取中途停止 | 文件中途被截断，或 byte 已损坏 | 6.3 |
| 可以读取，但关键帧缺失、顺序错乱 | 关键帧的链已损坏 | 6.4 |

### 6.2 修复溢出的值

下列值为 NaN、无穷大，或绝对值在 3.40282 × 10^38 以上时，替换为 0.001。

| 对象 | 值 |
| --- | --- |
| 骨骼 | 关键帧与当前状态的移动与旋转 |
| 配件 | 关键帧与当前状态的位置与旋转 |
| 相机 | 关键帧与当前状态的位置、偏移、旋转、距离 |
| 重力 | 关键帧与当前状态的加速度与方向 |

照明的颜色、表情的权重、描边粗细、配件的透明度与缩放，与物理计算无关，因此不处理。

### 6.3 从中途被截断的 PMM 中抢救动作

1. 按规格从头读取，保留读完的模型块。记录停止的位置。
2. 在停止的模型块中，按骨骼关键帧、表情关键帧的顺序，保留读到的部分。
3. 对读取成功的各模型，按 5.1 的步骤提取为 VMD。
4. 如果读到了相机区块，也按 5.2 的步骤提取相机。

中途的 byte 损坏而无法继续读取时，查找下一个模型块的开头并重新读取。模型块的开头依次是：模型 ID（u8）、两个带长度的名称、以 `.pmx` 或 `.pmd` 结尾的 256 byte 路径。以路径的字符串为线索查找位置，从名称长度吻合的位置重新读取。

### 6.4 修复关键帧的链

1. 对每个要素，收集初始记录和属于该要素的追加记录。因链已损坏而无法判断归属的关键帧，丢弃。
2. 按 2.3 的步骤重新组建链。

### 6.5 修复之后的确认

1. 重新读取写出的 PMM，确认能读到最后一个 byte。
2. 确认所有关键帧的链满足 PMM 2.3 的规则。
3. 确认检验的第 3 章至第 6 章的项目中没有错误和警告。

## 7. 打包与路径的重新链接

### 7.1 打包（收集）

将 PMM 使用的所有文件汇集到一个文件夹，使该文件夹单独就能打开。目录结构示例如下。

| 输出 | 内容 |
| --- | --- |
| `<输出>\<PMM 名>.pmm` | 路径已改写的 PMM |
| `<输出>\<PMM 名>.emm` | 路径已改写的 EMM |
| `<输出>\Files\Models\000\` 起 | 模型及其依赖文件，每个模型一个 3 位数的文件夹 |
| `<输出>\Files\Accessories\000\` 起 | 配件及其依赖文件 |
| `<输出>\Files\Media\` | 音频、背景视频、背景图片 |
| `<输出>\Files\` 之下 | EMM 所引用的效果，保持原来的层级 |
| `<输出>\manifest.txt` | 已收集文件的列表（UTF-8） |

步骤：

1. 将 PMM 中模型、配件、音频、背景视频、背景图片的路径，解析为实际存在的文件。相对路径先在 PMM 的文件夹中查找，再在 MMD 的执行文件夹中查找。
2. 追踪各文件的依赖文件（7.2）。
3. 复制依赖文件，保持与原文件的相对位置。
4. 将 PMM 的路径改写为复制目标的绝对路径。路径超过 255 byte 时中止。
5. 将 EMM 的路径（`[Object]` 与效果的行）改写为复制目标。
6. 用与原文件相同的字符编码写出 PMM 与 EMM。

### 7.2 依赖文件的追踪

| 源文件 | 依赖文件 |
| --- | --- |
| pmx | 材质的纹理、球面贴图、卡通贴图。共用卡通（用编号引用）与 `screen.bmp` 由 MMD 提供，不收集 |
| pmd | 材质的纹理名（多个名称以 `*` 分隔） |
| x（文本格式） | 内部写明的纹理文件名。如果有同名的 fx 文件，也包括在内 |
| x（二进制格式） | 无法追踪。告知用户 |
| fx、fxsub | `#include` 的引用，以及引号内带扩展名的文件名。被引用的 fx 文件递归追踪 |

依赖文件的相对路径，依次在引用方文件所在的文件夹、最上层文件所在的文件夹、以及它们共同的文件夹中查找。

### 7.3 路径的重新链接（迁移）

对整个文件夹一并搬迁后的工程，改写 PMM 与 EMM 中的绝对路径，使其指向新的位置。这不是对失效路径的搜索。

1. 确定搬迁前的共同文件夹（源根）：PMM 所在位置以及 PMM 与 EMM 中所有绝对路径共有的最深的文件夹。
2. 确定搬迁后的文件夹（目标根）。
3. 将 EMM 中以 `UserFile` 开头的相对路径（EMM 5.2），按下列顺序转换为绝对路径。
   1. 在源根之下的 `UserFile` 文件夹中找到时，采用该绝对路径，并纳入改写对象。
   2. 仅在 MMD 执行文件夹的 `UserFile` 中找到时，视为共享素材，不改写。
   3. 两处都找不到时，停止并显示列表。
4. 对所有绝对路径，将开头的源根替换为目标根。只要有路径不以源根开头，就在不做任何更改的情况下停止，并显示列表。
5. 写出新的 PMM 与同名的 EMM。

## 8. 从零创建 PMM

由指定的模型与动作创建新 PMM 的步骤。

### 8.1 步骤

1. 用 8.2 的值，建立没有模型和配件的 PMM 骨架。
2. 对每个模型，由 PMX 生成各列表（[PMX 的参照部分](06-pmx-reference.md)的第 4 章）。路径以绝对路径书写。
3. 用 8.3 的值，建立各模型的块。
4. 按 5.3 的步骤导入动作的 VMD。如果有相机的 VMD，则导入相机关键帧。
5. 将播放的结束帧和各模型的最终帧，设为不小于关键帧的最大帧。
6. 按 2.3 与 2.4 的步骤写出。

### 8.2 PMM 整体的值

这些是实际文件中常见的值，不一定与刚启动的 MMD 的值相同。

| 项目 | 值 |
| --- | --- |
| 识别字符串 | `Polygon Movie maker 0002` 加 6 个 NUL byte |
| 输出宽度、高度 | 1920、1080 |
| 侧栏宽度 | 430 |
| 视角 | 30 |
| 画面状态 | 全部为 1 |
| 相机的初始关键帧 | 距离 −45、位置 (0, 10, 0)、旋转 0、父级 (−1, 0)、插值全部 (20, 20, 107, 107)、透视 0、视角 30、选中 0 |
| 当前相机 | 位置与距离同初始关键帧、偏移 0、旋转 0、透视 0 |
| 照明的初始关键帧与当前照明 | 颜色各通道 0.602、方向 (−0.5, −1.0, 0.5) |
| 配件 | 选中 0、滚动 0、数量 0 |
| 编辑与播放 | 当前帧 0、滚动 0、骨骼操作 0、追踪目标 0、循环等标志全部 0、播放开始 0 与结束（最大帧） |

## 9. 其他整理

### 9.1 删除多余的关键帧

删除下列关键帧，不会改变播放的结果。

| 对象 | 删除的关键帧 |
| --- | --- |
| 骨骼 | 前后两个关键帧与自身这三者的移动、旋转、物理状态完全相同时，位于中间的关键帧。保留最初与最后的关键帧 |
| 骨骼 | 对于所有关键帧的移动都是 0、没有旋转、物理状态不变的骨骼，除初始关键帧外的所有关键帧 |
| 表情 | 前后两个关键帧的权重相同时，位于中间的关键帧。保留最初与最后的关键帧 |

不考虑插值曲线。前后的值相同时，无论曲线的形状如何，中间的值都不会改变。

### 9.2 关闭物理计算

将物理计算的模式（PMM 9.1 的项目 31）设为 0。

### 9.3 更改字符编码

1. 用原来的字符编码读取 PMM 与 EMM（2.2）。
2. 确认名称与路径能用新的字符编码书写。有无法书写的字符时，告知用户并停止。
3. 确认骨骼名与表情名在新的字符编码中不超过 19 byte。超过的名称，在 MMD 读取时将与 PMX 的名称不一致。
4. 用新的字符编码写出。
